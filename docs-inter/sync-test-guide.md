## 1. 前置条件

### 1.1 环境准备

| 项目 | 要求 |
|------|------|
| 服务器 | 已部署 QuantaNote 同步服务，`/health` 端点返回 200 |
| 客户端 | 至少 1 台安装 QuantaNote 桌面端（多设备测试需 2+ 台） |
| 数据库 | 使用全新数据库文件（删除 `~/.quantanote/quanta_note.sqlite`） |
| 网络 | 客户端可访问服务器地址 |

### 1.2 同步相关数据库表

```
settings          — 存储 SyncConfig JSON（key='quantanote-sync-config'）
sync_baseline     — 上次同步时每条记录的 content_hash（三方 diff 基线）
sync_tombstones   — 已删除记录的标记（防止删除复活）
```

### 1.3 同步的业务表

| 表名 | 同步标识 | 说明 |
|------|---------|------|
| items | id (UUID) | 笔记/文档 |
| tags | uuid (UUID) | 标签（自增 id 不参与同步） |
| item_tags | item_id + tag_uuid | 笔记-标签关联 |
| attachments | id (UUID) | 附件元数据 |
| versions | id (UUID) | 版本历史 |
| sync_tombstones | record_id + table_name | 删除标记 |

## 2. 认证模块

### 2.1 注册

**前置**：服务器可达，未登录状态

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| AUTH-01 | 正常注册 | 填写邮箱+密码，点击注册 | 注册成功，自动登录，config 中有 access_token 和 user_id |
| AUTH-02 | 重复邮箱注册 | 使用已注册邮箱再次注册 | 返回错误"邮箱已注册" |
| AUTH-03 | 弱密码注册 | 输入 1-2 位密码 | 返回密码强度不足错误 |
| AUTH-04 | 无效邮箱格式 | 输入 `abc` 而非 `abc@xx.com` | 返回邮箱格式错误 |
| AUTH-05 | 服务器不可达 | 填写错误服务器地址 | 连接超时/拒绝错误 |

### 2.2 登录

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| AUTH-06 | 正常登录 | 填写正确邮箱+密码 | 登录成功，config 保存到 SQLite |
| AUTH-07 | 错误密码 | 输入错误密码 | 返回"密码错误" |
| AUTH-08 | 不存在的邮箱 | 输入未注册邮箱 | 返回"用户不存在" |
| AUTH-09 | 登录后 config 持久化 | 登录后关闭应用重启 | 重启后仍为登录状态 |
| AUTH-10 | device_id 自动生成 | 首次登录时 | config.device_id 非空且为 UUID 格式 |

### 2.3 注销

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| AUTH-11 | 正常注销 | 点击注销按钮 | access_token 清空，enabled 设为 false |
| AUTH-12 | 注销后同步被禁用 | 注销后点击"立即同步" | 返回"未登录"错误 |
| AUTH-13 | 注销后自动同步停止 | 开启自动同步后注销 | 定时器被清除，不再触发同步 |

### 2.4 忘记密码 / 重置密码

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| AUTH-14 | 忘记密码 | 输入注册邮箱 | 返回 reset_token |
| AUTH-15 | 重置密码 | 使用 reset_token + 新密码 | 密码重置成功，可用新密码登录 |
| AUTH-16 | 无效 reset_token | 使用过期/错误 token | 返回重置失败错误 |

## 5. 首次同步

### 5.1 空客户端 → 有数据的服务端

**前置**：设备 A 已同步过（服务端有快照 S1），设备 B 全新安装

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| FIRST-01 | 首次同步拉取 | 设备 B 登录并同步 | 拉取 A 的所有记录，本地 DB 写入 items/tags/item_tags/versions/attachments |
| FIRST-02 | 基线创建 | 首次同步完成后 | sync_baseline 表写入所有记录的 hash |
| FIRST-03 | 附件文件下载 | A 有附件的笔记 | B 的 `~/.quantanote/attachments/` 下载附件文件 |
| FIRST-04 | 标签关联正确性 | A 有"工作"标签关联到笔记 | B 的 tags 表有"工作"标签（uuid 一致），item_tags 关联正确 |

### 5.2 有数据的客户端 → 空服务端

**前置**：设备 A 本地有数据，首次登录（服务端无快照）

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| FIRST-05 | 首次同步推送 | 设备 A 登录并同步 | 所有本地记录推送到服务端，创建快照 S1 |
| FIRST-06 | 附件上传 | A 本地有附件 | 附件文件上传到服务端对象存储 |
| FIRST-07 | 快照创建 | 同步完成后 | 服务端有快照记录，record_count 与本地一致 |

### 5.3 双方都有数据（首次相遇）

**前置**：设备 A 和 B 各自独立使用，有不同数据，现在登录同一账号首次同步

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| FIRST-08 | 双向合并 | A 先同步，B 后同步 | A 推送自己的数据；B 推送自己的 + 拉取 A 的 |
| FIRST-09 | 无冲突 | A 和 B 没有相同 ID 的记录 | 所有记录合并，无冲突 |
| FIRST-10 | 基线正确 | 双方同步完成后 | 两台设备的 sync_baseline 内容一致 |

## 8. 冲突解决

### 8.1 冲突检测

**前置**：A 和 B 都有笔记 X（上次同步时 hash=H0），现在各自修改

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| CONF-01 | 双方异改检测 | A 修改 X 并同步，B 也修改 X 后同步 | B 同步时检测到冲突（双方 hash 都 ≠ 基线） |
| CONF-02 | 双方同改同内容 | A 和 B 修改为相同内容后同步 | 无冲突（hash 相同） |
| CONF-03 | 仅一方修改 | A 修改 X 并同步，B 未修改 X 后同步 | 无冲突，B 拉取 A 的修改 |

### 8.2 策略：auto（自动，最新优先）

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| CONF-04 | 本地更新 | A 的 updated_at > B 的 updated_at | 选择本地版本（LocalWins） |
| CONF-05 | 远程更新 | B 的 updated_at > A 的 updated_at | 选择远程版本（RemoteWins） |
| CONF-06 | 时间戳相同 | 双方 updated_at 完全一致 | 选择远程版本（lt >= rt 时 LocalWins） |

### 8.3 策略：local-wins

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| CONF-07 | 冲突时本地优先 | 设置 local-wins，制造冲突 | 本地版本被推送，远程版本被忽略 |

### 8.4 策略：remote-wins

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| CONF-08 | 冲突时远程优先 | 设置 remote-wins，制造冲突 | 远程版本被拉取，本地修改丢失 |

### 8.5 策略：manual（手动选择）

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| CONF-09 | 检测到冲突暂停 | 设置 manual，制造冲突后同步 | 同步暂停（不 commit），弹出冲突解决对话框 |
| CONF-10 | 对话框显示冲突 | 查看冲突对话框 | 显示每条冲突的 record_id、表名、本地/远程更新时间 |
| CONF-11 | 选择本地 | 对某条冲突选择"本地" | 该记录使用本地版本推送 |
| CONF-12 | 选择远程 | 对某条冲突选择"远端" | 该记录使用远程版本拉取 |
| CONF-13 | 全部本地 | 点击"全部本地"按钮 | 所有冲突选择本地版本 |
| CONF-14 | 全部远程 | 点击"全部远端"按钮 | 所有冲突选择远程版本 |
| CONF-15 | 应用解决 | 点击"应用解决"按钮 | 冲突解决，同步完成，快照创建 |
| CONF-16 | 取消同步 | 点击"取消同步"按钮 | 放弃本次同步，清除 pending 状态 |
| CONF-17 | 应用重启恢复 | 冲突暂停后关闭应用重启 | 重启后自动检测到 pending 冲突，弹出对话框 |
| CONF-18 | 非冲突数据先行同步 | 有冲突和非冲突记录 | 非冲突记录先推送/拉取，冲突记录等待解决 |

| DEL-03 | 删除关联 | A 移除笔记标签后同步 | item_tags tombstone 推送 |

### 9.2 删除拉取

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| DEL-04 | 远程删除 → 本地删除 | A 删除并同步，B 同步 | B 的本地 DB 中对应记录被硬删除 |
| DEL-05 | 墓碑写入 | 拉取到删除记录 | 本地 sync_tombstones 表写入记录 |

### 9.3 删除复活防护

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|

| DEL-08 | 墓碑过期清理 | 同步时清理 90 天前的墓碑 | 旧墓碑从 sync_tombstones 表删除 |

## 10. 附件同步

### 10.1 附件上传

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| ATT-01 | 新附件上传 | 创建带附件的笔记后同步 | 附件文件上传到服务端，attachments_uploaded=1 |
| ATT-02 | 多附件上传 | 创建带多个附件的笔记 | 所有附件逐一上传 |
| ATT-03 | 附件元信息 | 上传完成后 | 服务端有 attachment 元信息（id, item_id, filename, mime_type, file_size, file_hash） |

### 10.2 附件下载

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| ATT-04 | 远程附件下载 | A 有附件并同步，B 同步 | B 下载附件文件到 `~/.quantanote/attachments/{item_id}/{filename}` |
| ATT-05 | 本地记录创建 | B 无附件记录时下载 | 自动创建 attachments 表记录 |
| ATT-06 | 附件文件存在 | 本地已有附件文件但记录丢失 | 重新创建记录（不重复下载文件） |

### 10.3 附件差异比对

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| ATT-07 | 差异检测 | A 有附件 X，B 无 | diff 结果：X 在 missing 列表 |
| ATT-08 | 无差异 | A 和 B 有相同附件 | missing=[]，无需上传下载 |
| ATT-09 | 文件 hash 比对 | 附件通过 SHA256 hash 比对 | hash 相同的附件不重复传输 |

## 14. 错误处理与边界场景


### 冲突制造方法

```
1. 设备 A 和 B 都同步到最新状态
2. 断开设备 B 的网络
3. 在设备 A 上修改 "测试笔记 1" 的标题为 "A 的修改"
4. 设备 A 同步（推送到服务端）
5. 在设备 B 上修改 "测试笔记 1" 的标题为 "B 的修改"
6. 恢复设备 B 的网络
7. 设备 B 同步 → 触发冲突
```
