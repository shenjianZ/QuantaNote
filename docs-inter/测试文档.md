## 1. 测试环境

### 1.1 依赖要求

| 组件 | 版本 | 说明 |
|------|------|------|
| Node.js | >=18 | 前端运行时 |
| pnpm | >=8 | 包管理器 |
| Rust | stable | 后端编译 |
| Tauri CLI | 2.x | 桌面应用框架 |

### 1.2 项目启动

```bash
# 安装依赖
pnpm install

# 前端构建检查
pnpm build

# 后端类型检查
cargo check --manifest-path src-tauri/Cargo.toml

# 启动开发模式
pnpm tauri dev
```

### 1.3 数据库位置

- 路径：`~/.quantanote/quanta_note.sqlite`（Windows: `%USERPROFILE%\.quantanote\quanta_note.sqlite`）
- 模式：WAL (Write-Ahead Logging)
- 外键约束：启用

### 1.4 测试数据准备

```sql
-- 插入测试笔记
INSERT INTO items (id, title, item_type, content, summary, created_at, updated_at)
VALUES ('item-test1', '测试笔记', 'note', '# 测试内容', '测试内容摘要', datetime('now'), datetime('now'));

-- 插入测试标签
INSERT INTO tags (name, color) VALUES ('测试标签', 'cyan');
```

## 2. 数据库层测试

### 2.1 Schema 完整性验证

#### TC-DB-001: 验证 items 表结构

**优先级:** P0

**步骤:**
1. 使用 SQLite 客户端连接 `quanta_note.sqlite`
2. 执行 `PRAGMA table_info(items);`

**预期结果:**
| cid | name | type | notnull | dflt_value | pk |
|-----|------|------|---------|------------|----|
| 0 | id | TEXT | 1 | NULL | 1 |
| 1 | title | TEXT | 1 | NULL | 0 |
| 2 | item_type | TEXT | 1 | NULL | 0 |
| 3 | content | TEXT | 1 | '' | 0 |
| 4 | summary | TEXT | 1 | '' | 0 |
| 5 | pinned | INTEGER | 1 | 0 | 0 |
| 6 | favorite | INTEGER | 1 | 0 | 0 |
| 7 | encrypted | INTEGER | 1 | 0 | 0 |
| 8 | created_at | TEXT | 1 | NULL | 0 |
| 9 | updated_at | TEXT | 1 | NULL | 0 |

#### TC-DB-002: 验证 tags 表结构

**优先级:** P0 — 与 TC-DB-001 相同的验证方式。

**预期字段:** id (INTEGER PK AUTOINCREMENT), name (TEXT NOT NULL UNIQUE), color (TEXT NOT NULL DEFAULT 'cyan')

#### TC-DB-003: 验证 item_tags 表结构

**优先级:** P0

**预期字段:** item_id (TEXT NOT NULL, FK→items), tag_id (INTEGER NOT NULL, FK→tags), PRIMARY KEY (item_id, tag_id)

#### TC-DB-004: 验证 attachments 表结构

**优先级:** P0

**预期字段:** id (TEXT PK), item_id (TEXT NOT NULL, FK→items), filename (TEXT NOT NULL), file_path (TEXT NOT NULL), mime_type (TEXT NOT NULL DEFAULT ''), file_size (INTEGER NOT NULL DEFAULT 0), created_at (TEXT NOT NULL)

#### TC-DB-005: 验证 versions 表结构

**优先级:** P0

**预期字段:** id (TEXT PK), item_id (TEXT NOT NULL, FK→items), version_number (INTEGER NOT NULL), content (TEXT NOT NULL DEFAULT ''), change_summary (TEXT NOT NULL DEFAULT ''), name (TEXT NOT NULL DEFAULT ''), description (TEXT NOT NULL DEFAULT ''), created_at (TEXT NOT NULL)

#### TC-DB-006: 验证 FTS5 虚拟表存在

**优先级:** P0

**SQL 验证:**
```sql
SELECT name FROM sqlite_master WHERE type='table' AND name LIKE '%fts%';
```
**预期:** 返回 `items_fts` 和 `items_fts_trigram` 两张表。

#### TC-DB-007: 验证触发器完整

**优先级:** P0

**SQL 验证:**
```sql
SELECT name FROM sqlite_master WHERE type='trigger' ORDER BY name;
```
**预期:** 返回 6 个触发器：`items_ai`, `items_ad`, `items_au`, `items_trigram_ai`, `items_trigram_ad`, `items_trigram_au`

### 2.2 CRUD 操作测试

#### TC-DB-010: INSERT 创建笔记

**优先级:** P0

**操作:**
```sql
INSERT INTO items (id, title, item_type, content, summary, created_at, updated_at)
VALUES ('crud-test-1', 'CRUD测试标题', 'note', 'CRUD测试内容', '摘要', datetime('now'), datetime('now'));
```

**验证:**
- `SELECT COUNT(*) FROM items WHERE id='crud-test-1'` → 1
- `SELECT title, item_type FROM items WHERE id='crud-test-1'` → ('CRUD测试标题', 'note')
- FTS5 索引自动更新：`SELECT COUNT(*) FROM items_fts WHERE items_fts MATCH 'CRUD测试'` → >= 1
- Trigram 索引更新：`SELECT COUNT(*) FROM items_fts_trigram WHERE items_fts_trigram MATCH '"CRUD"'` → >= 1

#### TC-DB-011: UPDATE 更新笔记

**优先级:** P0

**操作:**
```sql
UPDATE items SET title='更新后的标题', content='更新后的内容', updated_at=datetime('now')
WHERE id='crud-test-1';
```

**验证:**
- `SELECT title, content FROM items WHERE id='crud-test-1'` → ('更新后的标题', '更新后的内容')
- FTS5 索引同步：旧内容移除，新内容可搜索

#### TC-DB-012: DELETE 删除笔记（级联测试）

**优先级:** P0

**前置条件:** 为 `crud-test-1` 添加标签关联和附件。

**操作:**
```sql
DELETE FROM items WHERE id='crud-test-1';
```

**验证:**
- items 表记录消失
- item_tags 中关联记录自动删除（ON DELETE CASCADE）
- attachments 中关联记录自动删除
- versions 中关联记录自动删除
- FTS5 虚拟表中条目同步删除

### 2.3 FTS5 搜索测试

#### TC-DB-020: unicode61 英文分词搜索

**优先级:** P0

**前置条件:** 存在标题含 "rust programming guide" 的笔记。

**SQL:**
```sql
SELECT i.id, i.title FROM items_fts f
JOIN items i ON i.rowid = f.rowid
WHERE items_fts MATCH 'rust programming'
ORDER BY rank LIMIT 50;
```

**预期:** 返回匹配的笔记，按 BM25 排名排序。

#### TC-DB-021: trigram 中文子串搜索

**优先级:** P0

**前置条件:** 存在标题含 "数据库设计文档" 的笔记。

**SQL:**
```sql
SELECT i.id, i.title FROM items_fts_trigram f
JOIN items i ON i.rowid = f.rowid
WHERE items_fts_trigram MATCH '"数据库"'
ORDER BY rank LIMIT 50;
```

**预期:** 能匹配 "数据库设计文档"、"数据库" 等包含该子串的笔记。

#### TC-DB-022: 前缀搜索

**优先级:** P1

**操作:** 搜索 `"rus"*` 应匹配 "rust", "rustacean" 等。

### 2.4 触发器测试

#### TC-DB-030: INSERT 触发器同步 FTS5

**优先级:** P0

**步骤:**
1. INSERT 一条新记录到 items
2. 立即通过 FTS5 查询该记录内容

**预期:** FTS5 查询可立即检索到新插入的内容。

#### TC-DB-031: UPDATE 触发器同步 FTS5

**优先级:** P0

**步骤:**
1. 更新一条现有记录的 content
2. 用旧内容搜索 → 无结果
3. 用新内容搜索 → 有结果

**预期:** FTS5 索引与 items 表内容保持一致。

### 2.5 外键约束测试

#### TC-DB-040: 外键级联删除

**优先级:** P0

**验证链:**
- 删除 items → item_tags 中对应关联自动删除
- 删除 items → attachments 中对应附件自动删除
- 删除 items → versions 中对应版本自动删除
- 删除 tags → item_tags 中对应关联自动删除

## 3. 后端 API 测试

所有 Tauri Command 通过 `invoke("command_name", { args })` 调用，返回 `Result<T, AppError>`。

### 3.1 Item Commands (7 个)

#### TC-API-001: create_item — 创建笔记

**优先级:** P0

**调用:**
```ts
invoke("create_item", { title: "新笔记", itemType: "note", content: "# Hello World" })
```

**预期返回 (ItemDto):**
```json
{
  "id": "item-xxxxxxxxxxxx",
  "title": "新笔记",
  "item_type": "note",
  "content": "# Hello World",
  "summary": "# Hello World",
  "pinned": false,
  "favorite": false,
  "encrypted": false,
  "created_at": "2026-04-30T...",
  "updated_at": "2026-04-30T..."
}
```

**验证点:**
1. id 格式为 `item-` + 12 位 hex
2. summary 为 content 的前 100 字符
3. created_at 和 updated_at 相同
4. 同时在 versions 表中生成一条初始版本（version_number=1, change_summary="创建", name="初始版本"）

#### TC-API-002: create_item — 标题为空应报错

**优先级:** P0 — 调用 `create_item` 时 title 为空字符串。

**预期:** 返回 `AppError::Validation("标题不能为空")`

#### TC-API-003: create_item — content 为空

**优先级:** P1 — content 参数不传。

**预期:** 返回的 ItemDto.content 为空字符串，summary 为空。仍自动创建初始版本。

#### TC-API-004: get_items — 获取笔记列表

**优先级:** P0

**调用:**
```ts
invoke("get_items", { itemType: "note", limit: 50, offset: 0 })
```

**预期返回:** `Vec<ItemDto>`，按 `updated_at DESC` 排序，最多 50 条。itemType 不传时返回所有类型。

#### TC-API-005: get_items — 空数据库

**优先级:** P1 — 在没有 items 的情况下调用。

**预期:** 返回空数组 `[]`。

#### TC-API-006: get_item — 获取单个笔记

**优先级:** P0

**调用:**
```ts
invoke("get_item", { id: "item-test1" })
```

**预期返回:** 对应 ItemDto，若 id 不存在返回 `AppError::NotFound`。

#### TC-API-007: update_item — 更新笔记

**优先级:** P0

**调用:**
```ts
invoke("update_item", {
  id: "item-test1",
  title: "更新标题",
  content: "更新内容",
  pinned: true,
  favorite: true
})
```

**预期:**
- 返回更新后的 ItemDto，title/content/pinned/favorite 已更新
- updated_at 时间戳更新
- FTS5 索引同步更新
- 不传的字段保持不变（partial update）

#### TC-API-008: update_item — 更新不存在的笔记

**优先级:** P1 — 使用不存在的 id。

**预期:** 返回 `AppError::NotFound("未找到笔记: xxx")`

#### TC-API-009: delete_item — 删除笔记

**优先级:** P0

**调用:**
```ts
invoke("delete_item", { id: "item-test1" })
```

**验证:**
- 返回 `Ok(())`
- items 表中记录已删除
- 关联的 item_tags、attachments、versions 级联删除
- FTS5 索引同步删除
- 若物理附件文件存在，文件也被删除

#### TC-API-010: delete_item — 删除不存在的笔记

**优先级:** P1 — 使用不存在的 id。

**预期:** 返回 `AppError::NotFound`

#### TC-API-011: get_pinned_items — 获取置顶笔记

**优先级:** P0

**调用:** `invoke("get_pinned_items")`

**预期:** 返回 `pinned=true` 的 ItemDto 列表，按 updated_at DESC 排序。

#### TC-API-012: get_recent_items — 获取最近笔记

**优先级:** P0

**调用:** `invoke("get_recent_items", { limit: 20 })`

**预期:** 返回最多 20 条 ItemDto，按 updated_at DESC。不传 limit 时默认 20。

#### TC-API-014: optimize_db — 优化数据库

**优先级:** P1

**调用:** `invoke("optimize_db")`

**预期:** 返回 `Ok(())`，执行 `PRAGMA incremental_vacuum` 并重建 FTS5 索引。

## 6. 边界和异常测试

### 6.1 输入边界

#### TC-EDGE-001: 超长标题

**优先级:** P2 — 创建标题超过 10000 字符的笔记。

**预期:** 不崩溃。TEXT 类型无长度限制，但 UI 应合理截断显示。

#### TC-EDGE-002: 超长内容

**优先级:** P2 — 创建内容超过 1MB 的 Markdown 笔记。

**预期:** 不崩溃，但可能影响编辑器性能。FTS5 索引可能需要更长时间。

#### TC-EDGE-003: 标题仅含特殊字符

**优先级:** P2 — 标题为 `!@#$%^&*()_+-=[]{}|;':",./<>?`

**预期:** 创建成功，搜索时可正确转义。

#### TC-EDGE-004: 标题仅含空白字符

**优先级:** P0 — 标题为空格/换行。

**预期:** 后端 `item_service::create_item` 校验标题非空，返回 Validation 错误。

#### TC-EDGE-005: 空内容笔记

**优先级:** P1 — 创建 content 为空的笔记。

**预期:** 创建成功，summary 为空字符串，初始版本 content 为空。

#### TC-EDGE-006: 标签名重复创建

**优先级:** P1

**预期:** 第二次创建同名标签时返回 Database 错误（UNIQUE 约束冲突），前端应妥善处理。

#### TC-EDGE-007: 查询字符串含 SQL 注入尝试

**优先级:** P0 — 搜索输入 `'; DROP TABLE items; --`

**预期:** 安全。所有查询使用参数化绑定（rusqlite `?1` 占位符），不拼接 SQL。

#### TC-EDGE-008: 查询字符串含 FTS5 特殊字符

**优先级:** P1 — 搜索输入 `C++ * AND OR NOT`

**预期:** 不崩溃。后端 `escape_like` 转义 `\`, `%`, `_`；FTS5 查询语法错误时 fallback 到 LIKE。
