# 备份

QuantaNote 内置的自动备份和手动备份都会生成**逻辑 ZIP 备份**。它不是运行中的 SQLite 数据库文件副本，而是将笔记、标签、版本和附件按照 QuantaNote 的 ZIP 格式打包，之后可以通过应用的导入功能恢复或迁移。

## 自动备份

自动备份会在应用运行期间按照设定的时间间隔创建 ZIP 文件。应用未运行时不会触发定时任务。

**启用自动备份：**

1. 打开 **设置 > 数据管理**
2. 找到「自动备份」
3. 开启开关
4. 配置备份间隔、最大数量和过期时长

每次自动备份都会先写入备份目录中的隐藏临时文件，再检查 ZIP 结构、JSON 内容和附件哈希。只有校验成功后，文件才会原子重命名为正式备份；失败的临时文件会被清理，不会被列为可用备份。

## 备份配置

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 备份间隔 | 7 天 | 两次自动备份之间的时间间隔 |
| 最大备份数 | 10 | 自动备份最多保留的文件数量 |
| 过期时长 | 90 天 | 自动备份超过此时长后会被清理 |

数量和过期策略只作用于自动备份。自动备份文件使用 `auto-backup-` 前缀；旧版本生成的 `backup-` 文件仍按自动备份参与清理。

## 手动备份

在执行大量编辑、导入、升级或迁移前，可以在 **设置 > 数据管理** 点击「立即备份」。手动备份同样经过完整性校验，但使用 `manual-backup-` 前缀，并且**不受自动备份的数量和过期清理策略影响**。

设置页会记录最近一次成功备份的时间、文件名和大小。备份失败时，最近一次成功记录会保留，同时显示本次失败原因。

## 备份管理器与完整性检查

「备份管理」会显示备份类型、文件大小、创建时间和完整性状态：

- 「完整性已验证」表示 ZIP 结构、数据文件和附件哈希均检查通过。
- 「校验失败」表示文件可能损坏或不完整，详情中会显示失败原因。
- 点击每个备份旁的检查按钮，可以重新执行完整性检查。
- 删除操作不可撤销；删除前应确认该文件不再需要。

完整性检查只读取备份，不会把数据写回当前数据库。真正恢复时，请使用 **设置 > 数据管理 > 导入**，并在导入前保留一份新的手动备份。

## 逻辑 ZIP 备份与 SQLite 文件备份的区别

QuantaNote 中有两类容易混淆的文件：

| 类型 | 位置/来源 | 用途 |
|------|------|------|
| 逻辑 ZIP 备份 | `backups/` 目录，由自动备份或「立即备份」生成 | 通过 QuantaNote 导入，适合恢复、迁移和长期归档；包含 `data.json`、`versions.json`、`manifest.json` 和附件文件 |
| SQLite 主数据库文件 | `quanta_note.sqlite` | 应用当前正在使用的本地数据库，不是「立即备份」生成的备份文件 |

不要把正在运行中的 `quanta_note.sqlite` 直接复制后当作可靠备份，也不要在未确认应用关闭的情况下用外部文件替换它。需要跨设备恢复或迁移时，优先使用经过校验的逻辑 ZIP，并通过应用导入。

## 存储位置

所有内置 ZIP 备份保存在：

```
~/.quantanote/backups/
```

Windows 默认路径为：

```
%USERPROFILE%\.quantanote\backups\
```

如果数据非常重要，建议在备份完成并通过完整性检查后，再将 ZIP 复制到外部磁盘或其他安全位置。只把备份留在与主数据库相同的设备上，无法防范设备损坏或丢失。
