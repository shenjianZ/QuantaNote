### 1.2 核心数据流原则

1. **所有持久化数据存储在 SQLite**：笔记、标签、关联、附件元数据、版本历史均存储在 SQLite 中
2. **设置存储在 localStorage**：主题、字体、窗口行为等偏好设置不经过后端，直接存在浏览器 localStorage
3. **附件文件存储在磁盘**：附件文件复制到 `~/.quantanote/attachments/`，数据库仅存元数据（路径、大小、MIME）
4. **JSON 格式跨进程通信**：前端通过 `invoke()` 调用后端，参数和返回值均为 JSON 序列化
5. **FTS5 自动同步**：对 items 表的 INSERT/UPDATE/DELETE 操作通过 6 个 SQLite 触发器自动同步到两张 FTS5 虚拟表

### 2.2 items 表 — 笔记/条目

存储所有笔记的核心数据。`item_type` 可区分不同条目类型，但当前版本主要使用 `"note"`。

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `id` | TEXT PK | — | 格式 `item-xxxxxxxxxxxx`（12位 hex UUID） |
| `title` | TEXT NOT NULL | — | 笔记标题，不可为空 |
| `item_type` | TEXT NOT NULL | — | 条目类型：note/link/file/image/code/task |
| `content` | TEXT NOT NULL | `''` | Markdown 格式的正文内容 |
| `summary` | TEXT NOT NULL | `''` | 摘要（自动取 content 前 100 字符） |
| `pinned` | INTEGER NOT NULL | `0` | 是否置顶（0/1 = false/true） |
| `favorite` | INTEGER NOT NULL | `0` | 是否收藏（0/1） |
| `encrypted` | INTEGER NOT NULL | `0` | 是否加密标记（预留字段，0/1） |
| `created_at` | TEXT NOT NULL | — | 创建时间（ISO 8601 格式） |
| `updated_at` | TEXT NOT NULL | — | 最后更新时间 |

**重要约束与索引：**
- `id` 为主键
- 通过 6 个触发器自动同步到 `items_fts` 和 `items_fts_trigram` 两张 FTS5 虚拟表

### 2.3 tags 表 — 标签

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `id` | INTEGER PK AUTOINCREMENT | — | 自增主键 |
| `name` | TEXT NOT NULL UNIQUE | — | 标签名（唯一） |
| `color` | TEXT NOT NULL | `'cyan'` | 颜色：cyan/green/blue/purple/yellow/red |

### 2.4 item_tags 表 — 笔记-标签关联（多对多）

| 字段 | 类型 | 说明 |
|------|------|------|
| `item_id` | TEXT NOT NULL | 外键 → items(id) ON DELETE CASCADE |
| `tag_id` | INTEGER NOT NULL | 外键 → tags(id) ON DELETE CASCADE |

- 复合主键：`(item_id, tag_id)`
- 删除笔记或标签时，关联记录自动级联删除

### 2.5 attachments 表 — 附件

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `id` | TEXT PK | — | 格式 `att-xxxxxxxxxxxx` |
| `item_id` | TEXT NOT NULL | — | 外键 → items(id) ON DELETE CASCADE |
| `filename` | TEXT NOT NULL | — | 原始文件名 |
| `file_path` | TEXT NOT NULL | — | 相对于 `~/.quantanote/` 的路径 |
| `mime_type` | TEXT NOT NULL | `''` | MIME 类型（根据扩展名自动识别） |
| `file_size` | INTEGER NOT NULL | `0` | 文件大小（字节） |
| `created_at` | TEXT NOT NULL | — | 添加时间 |

**关键说明：**
- `file_path` 存储的是**相对路径**，读取时通过 `quantanote_dir().join(relative_path)` 拼接为绝对路径
- 物理文件存储在 `~/.quantanote/attachments/` 目录
- 文件名冲突时自动追加编号：`file.txt` → `file_1.txt` → `file_2.txt`

### 2.6 versions 表 — 版本历史

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `id` | TEXT PK | — | 格式 `ver-xxxxxxxxxxxx` |
| `item_id` | TEXT NOT NULL | — | 外键 → items(id) ON DELETE CASCADE |
| `version_number` | INTEGER NOT NULL | — | 版本号（从 1 开始自增） |
| `content` | TEXT NOT NULL | `''` | 该版本的完整 Markdown 内容快照 |
| `change_summary` | TEXT NOT NULL | `''` | 变更说明 |
| `name` | TEXT NOT NULL | `''` | 版本名称（默认当前时间） |
| `description` | TEXT NOT NULL | `''` | 版本描述 |
| `created_at` | TEXT NOT NULL | — | 版本创建时间 |

### 2.7 FTS5 全文搜索虚拟表

QuantaNote 使用**双 FTS5 索引**策略来解决中英文混合搜索问题：

| 虚拟表 | 分词器 | 用途 |
|--------|--------|------|
| `items_fts` | `unicode61` | 英文分词搜索（前缀匹配、词组匹配） |
| `items_fts_trigram` | `trigram` | 中文子串搜索（3-gram 滑动窗口） |

两张表均为**外部内容表**（`content=items, content_rowid=rowid`），即 FTS5 不独立存储数据副本，而是引用 `items` 表的行。读取时通过 JOIN 获取完整数据：

```sql
SELECT i.id, i.title, i.item_type, COALESCE(substr(i.content, 1, 100), '') as summary
FROM items_fts f
JOIN items i ON i.rowid = f.rowid
WHERE items_fts MATCH '搜索词'
ORDER BY rank LIMIT 50;
```

**6 个触发器**确保 FTS5 索引与 items 表保持同步：每次 INSERT/UPDATE/DELETE 操作都自动更新两张虚拟表。

## 3. 核心数据流程

> 以下每个章节描述一个完整的 UI 交互场景，从前端组件触发，到后端处理，到数据库写入，再到数据回显的全链路。

### 3.1 创建笔记

QuantaNote 支持两种创建笔记的方式：**工作台快速记录**和**记录库新建**。

#### 3.1.1 触发入口

| 入口 | 组件 | 触发方式 |
|------|------|----------|
| 工作台快速记录 | `WorkspacePage.tsx` | 输入 Markdown 内容后点击"记录"按钮或 `Ctrl+Enter` |
| 记录库新建 | `LibraryPage.tsx` | 点击"新建笔记"按钮 |
| 全局快捷键 | `QuantaNoteApp.tsx` | `Ctrl+N` 创建空白笔记并打开编辑器 |

#### 3.1.2 前端处理流程（工作台快速记录）

```
WorkspacePage.tsx (第 34-62 行)
│
├─ 1. 用户在 Vditor 编辑器中输入 Markdown 内容
│    状态: draft = "# 会议纪要\n\n- 项目进度\n- 下周计划"
│
├─ 2. 点击 "记录" 按钮 → handleQuickSave()
│    ├─ 从 draft 中提取首行作为标题
│    │  标题 = "会议纪要"（去除 # 等 Markdown 标记）
│    ├─ 调用 onQuickCreate(content) prop
│    └─ 保存成功后：清空 draft，显示"已保存"（1.8秒后消失）
│
└─ 3. QuantaNoteApp.tsx 中的 handleQuickCreate (第 51-62 行)
     ├─ 调用 itemStore.createItem(title, "note", content)
     └─ 成功后调用 itemStore.getItem(id) 获取完整 ItemDto
```

#### 3.1.3 Zustand Store 处理

```
itemStore.ts — createItem (第 64-72 行)
│
├─ 调用: invoke("create_item", { title, itemType: "note", content })
│
└─ 成功返回 ItemDto 后:
     ├─ 将新笔记插入 items 数组头部
     └─ 返回 ItemDto
```

#### 3.1.4 Tauri Command 处理

```
commands/item.rs — create_item (第 8-16 行)
│
└─ 委托 → item_service::create_item(db, title, item_type, content)
```

#### 3.1.5 Service 层处理

```
services/item_service.rs — create_item (第 7-37 行)
│
├─ 1. 验证: 如果 title.trim().is_empty() → Validation 错误
│
├─ 2. 设置默认值:
│    content = content.unwrap_or_default()  // 空则 ""
│    summary = content.chars().take(100).collect()  // 前 100 字符
│
├─ 3. 调用 item_repository::create(db, payload)
│    └─ INSERT INTO items (id, title, item_type, content, summary, created_at, updated_at)
│       VALUES (?1, ?2, ?3, ?4, ?5, ?6, ?6)
│       【注意: created_at 和 updated_at 设为同一时间戳】
│
└─ 4. 如果 content 非空，自动创建初始版本:
     └─ version_repository::create_version(db, item_id, content, "创建", "初始版本", "")
        └─ INSERT INTO versions (id, item_id, version_number, content, change_summary, name, description, created_at)
           VALUES (?1, ?2, 1, ?4, '创建', '初始版本', '', ?8)
```

#### 3.1.6 数据库写入详情

**步骤 1: INSERT INTO items**
```sql
-- 实际执行的 SQL（参数化）
INSERT INTO items (id, title, item_type, content, summary, created_at, updated_at)
VALUES ('item-a1b2c3d4e5f6', '会议纪要', 'note', '# 会议纪要...', '# 会议纪要...', '2026-04-30T10:30:00', '2026-04-30T10:30:00');
```

**步骤 2: FTS5 触发器自动执行**（两套触发器共 3 个事件 × 2 = 6 条）
```sql
-- 触发器 items_ai 自动执行:
INSERT INTO items_fts(rowid, title, content, summary)
VALUES (NEW.rowid, NEW.title, NEW.content, NEW.summary);

-- 触发器 items_trigram_ai 自动执行:
INSERT INTO items_fts_trigram(rowid, title, content, summary)
VALUES (NEW.rowid, NEW.title, NEW.content, NEW.summary);
```
> 此时新笔记已可在 FTS5 搜索中被检索到。

**步骤 3: INSERT INTO versions（初始版本）**
```sql
INSERT INTO versions (id, item_id, version_number, content, change_summary, name, description, created_at)
VALUES ('ver-f6e5d4c3b2a1', 'item-a1b2c3d4e5f6', 1, '# 会议纪要...', '创建', '初始版本', '', '2026-04-30T10:30:00');
```

### 3.2 加载笔记列表

#### 3.2.1 触发时机

- 应用启动时（`QuantaNoteApp.tsx` 第 46 行 `fetchItems()`）
- 切换到记录库页面时
- 创建/更新/删除笔记后自动刷新

#### 3.2.2 完整数据流

```
QuantaNoteApp.tsx 初始化
  └─ itemStore.fetchItems("note")
       └─ invoke("get_items", { itemType: "note", limit: 50, offset: 0 })
            └─ item_service::get_items()
                 └─ item_repository::get_items(Some("note"), 50, 0)
```

**后端 SQL:**
```sql
SELECT id, title, item_type, content, summary, pinned, favorite, encrypted, created_at, updated_at
FROM items
WHERE item_type = 'note'
ORDER BY updated_at DESC
LIMIT 50 OFFSET 0;
```

> 不传 `itemType` 时，去掉 WHERE 条件，返回所有类型的条目。

### 3.3 查看笔记详情（阅读器）

### 3.4 编辑笔记（文档编辑器）

DocumentEditorPage 是全屏的 Vditor 编辑器页面。

#### 3.4.1 触发入口

### 3.6 搜索笔记

#### 3.6.1 搜索策略分层降级

```
search_service::search_items (第 83-164 行)
  │
  ├─ 输入清理 → 空查询返回空
  │
  └─ 判断 contains_cjk(query):
       │
       ├─ CJK >= 3 字符（中文路径）:
       │   ├─ 优先: trigram FTS5 精确匹配
       │   │   → search_repository::search_trigram
       │   │   → MATCH '"数据库" "设计"' (引号包裹)
       │   └─ Fallback: LIKE 子串匹配
       │       → WHERE title LIKE '%数据库%' OR content LIKE '%数据库%'
       │
       └─ CJK < 3 或无 CJK（英文路径）:
           ├─ 优先: unicode61 FTS5 前缀匹配
           │   → search_repository::search
           │   → MATCH '"rus"* "sql"*' (引号+星号)
           └─ Fallback: LIKE 子串匹配
```

#### 3.6.2 三种搜索 SQL 对比

| 策略 | SQL 模式 | 适用场景 | 优点 | 限制 |
|------|----------|----------|------|------|
| unicode61 FTS5 | `MATCH '"term"*'` | 英文前缀 | 高效、支持排名 | 不支持中文子串 |
| trigram FTS5 | `MATCH '"词" "词"'` | 中文精确 | 高效、中文子串 | 短词(<3字)效果差 |
| LIKE | `LIKE '%term%'` | 全部（降级） | 完全子串匹配 | 慢、无排名 |

#### 3.6.3 前端搜索层（CommandPalette 额外降级）

```
CommandPalette.tsx:
  ├─ 有后端结果 → 用 searchStore.results
  └─ 后端空结果 → 前端 includes 降级:
       items.filter(i => i.title.includes(q) || i.summary.includes(q))
```

#### 3.6.4 数据库操作汇总

| 操作 | SQL |
|------|-----|
| unicode61 FTS5 | `SELECT ... FROM items_fts f JOIN items i ... WHERE MATCH ?1 ORDER BY rank LIMIT 50` |
| trigram FTS5 | `SELECT ... FROM items_fts_trigram f JOIN items i ... WHERE MATCH ?1 ORDER BY rank LIMIT 50` |
| LIKE 降级 | `SELECT ... FROM items i WHERE ... LIKE ? ... ORDER BY updated_at DESC LIMIT 50` |

### 3.7 标签管理

#### 3.7.1 标签的三种操作场景

**场景 A: 全局标签 CRUD**
```
TagPickerModal / SettingsPage
  ├─ 创建标签: invoke("create_tag", { name, color })
  │   └─ INSERT INTO tags (name, color) VALUES (?1, ?2)
  ├─ 删除标签: invoke("delete_tag", { name })
  │   └─ DELETE FROM tags WHERE name = ?1
  │        └─ CASCADE: DELETE FROM item_tags WHERE tag_id = OLD.id
  └─ 获取全部: invoke("get_all_tags")
      └─ SELECT name, color FROM tags ORDER BY name
```

**场景 B: 为笔记设置标签**
```
TagPickerModal — onChange(tagNames)
  └─ tagStore.updateItemTags(itemId, tagNames)
       └─ invoke("set_item_tags", { itemId, tagNames })
            └─ tag_service::set_item_tags (第 26-37 行):
                 ├─ 1. DELETE FROM item_tags WHERE item_id = ?1  (清空旧关联)
                 ├─ 2. 遍历 tagNames:
                 │   ├─ SELECT id FROM tags WHERE name = ?1  (查找 tag_id)
                 │   ├─ 若不存在 → INSERT INTO tags (name, color) VALUES (?1, 'cyan')  (自动创建)
                 │   └─ INSERT OR IGNORE INTO item_tags (item_id, tag_id) VALUES (?1, ?2)
                 └─ 完成后前端调用 fetchItemTags + getAllItemTagMappings 刷新
```

**场景 C: 获取笔记的标签（用于显示）**
```
getItemTags(itemId)
  └─ SELECT t.name, t.color FROM tags t
     JOIN item_tags it ON it.tag_id = t.id
     WHERE it.item_id = ?1 ORDER BY t.name
```

**场景 D: 全量标签映射（用于列表筛选）**
```
getAllItemTagMappings()
  └─ SELECT it.item_id, t.name FROM item_tags it
     JOIN tags t ON t.id = it.tag_id ORDER BY it.item_id, t.name
  → 前端: Record<itemId, tagName[]> 查表
```

#### 3.7.2 标签自动创建机制

在 `set_item_tags` 过程中，如果传入不存在的标签名，**自动创建**该标签（颜色默认 "cyan"）。这意味着：
- 用户可以通过 TagPickerModal 的"新建标签"明确创建
- 也可以在 `set_item_tags` 中间接创建（tagNames 参数中传新名称）

#### 3.7.3 数据库操作汇总

| 操作 | SQL | 影响的表 |
|------|-----|----------|
| 创建标签 | `INSERT INTO tags (name, color) VALUES (?, ?)` | tags |
| 删除标签 | `DELETE FROM tags WHERE name = ?` | tags, item_tags (CASCADE) |
| 设置标签 | `DELETE FROM item_tags WHERE item_id=?` + 逐条 `INSERT OR IGNORE INTO item_tags` | item_tags |
| 获取标签列表 | `SELECT name, color FROM tags ORDER BY name` | tags（只读） |
| 获取笔记标签 | `SELECT t.name, t.color FROM tags t JOIN item_tags it ... WHERE it.item_id=?` | tags, item_tags（只读） |

## 5. 主题与设置系统

### 5.1 主题模式

三种模式通过 `data-theme` attribute 控制：

```html
<html data-theme="light">   <!-- 浅色模式 -->
<html data-theme="dark">    <!-- 深色模式 -->
<html data-theme="system">  <!-- 跟随系统 -->
```

系统模式下通过 CSS media query 自动切换：
```css
[data-theme="system"] { /* 继承 :root 浅色变量 */ }
@media (prefers-color-scheme: dark) {
  [data-theme="system"] { /* 深色变量覆盖 */ }
}
```

### 5.2 设置持久化与恢复

```
应用启动:
  ├─ settingsStore 构造函数:
  │   └─ loadSettings() → JSON.parse(localStorage("quantanote-settings"))
  │       └─ 合并默认值（缺失的键使用 DEFAULT_SETTINGS 补全）
  │
  ├─ settingsStore.init():
  │   └─ applySettings() → 将设置写入 CSS 自定义属性
  │
  ├─ appStore 构造函数:
  │   ├─ localStorage("quantanote-page") → currentPage
  │   └─ localStorage("quantanote-theme") → theme → data-theme
  │
  └─ appStore.setTheme():
      └─ applyThemeAttr() → documentElement.setAttribute('data-theme', theme)
```
