# 06 - 同步测试指南

> 本文档教你如何测试 QuantaNote 的同步功能，从环境搭建到具体的测试场景。
> 包含手动测试和自动化测试两部分。

---

## 一、测试环境准备

### 1.1 启动同步服务器

```powershell
# 进入服务器项目目录
cd web-rust-template-project

# 启动服务器（默认端口根据配置文件而定）
cargo run
```

确认服务器启动成功：访问 `http://localhost:{端口}/health` 应该返回 200。

### 1.2 启动 QuantaNote 客户端

```powershell
# 在项目根目录
pnpm tauri dev
```

### 1.3 需要的工具

- **两个浏览器实例**（或两个窗口）来模拟多设备——实际上 QuantaNote 是桌面应用，你需要：
  - 两台电脑，或者
  - 一台电脑上运行两个不同数据目录的实例（需要修改配置）
  - 最简单的方式：先在一台设备上操作，然后用同一账号在另一台设备上登录

## 二、手动测试场景

### P0 — 核心功能（必须通过）

#### P0-1：注册新账号

**步骤**：
1. 打开设置 → 同步面板
2. 输入服务器地址，点击"测试连接"
3. 确认显示"连接成功"
4. 点击"注册"
5. 输入邮箱和密码（至少 6 位），点击注册

**预期**：
- 注册成功后，状态变为"已登录"
- 自动开启同步功能

#### P0-2：登录已有账号

**步骤**：
1. 在另一台设备上打开设置 → 同步面板
2. 输入相同的服务器地址
3. 点击"登录"，输入邮箱和密码

**预期**：
- 登录成功，状态变为"已登录"

#### P0-3：首次同步（空设备拉取）

**步骤**：
1. 设备 A 有数据，设备 B 刚登录（空数据）
2. 设备 B 点击"立即同步"

**预期**：
- 同步完成后，设备 B 上出现设备 A 的所有笔记、标签
- 附件也能正确下载
- 同步历史中出现一条新记录

#### P0-4：增量同步（单方向修改）

**步骤**：
1. 设备 A 新建一条笔记
2. 设备 B 点击"立即同步"

**预期**：
- 设备 B 上出现新笔记
- 同步结果显示 pushed=0, pulled=1（或更多）

#### P0-5：双向同步（双方各自修改不同记录）

**步骤**：
1. 设备 A 修改笔记 X
2. 设备 B 修改笔记 Y
3. 两台设备分别同步

**预期**：
- 设备 A 同步后能看到笔记 Y 的变化
- 设备 B 同步后能看到笔记 X 的变化

#### P0-6：冲突解决 — 自动模式

**步骤**：
1. 确认冲突策略为"auto"（默认）
2. 设备 A 修改笔记 Z（内容改为"版本 A"）
3. 设备 B 修改同一条笔记 Z（内容改为"版本 B"）
4. 两台设备分别同步

**预期**：
- 后修改的版本胜出（按时间戳比较）
- 两台设备最终内容一致

#### P0-7：删除同步

**步骤**：
1. 设备 A 删除一条笔记
2. 设备 B 点击"立即同步"

**预期**：
- 设备 B 上该笔记消失
- 不会出现"幽灵记录"（删除又回来了）

---

### P1 — 重要功能

#### P1-1：冲突解决 — 手动模式

**步骤**：
1. 把冲突策略改为"手动"
2. 设备 A 和设备 B 同时修改同一笔记
3. 设备 B 同步

**预期**：
- 弹出冲突解决弹窗
- 显示冲突数量、表名、更新时间
- 可以逐条选择"本地"或"远程"
- 可以"全选本地"或"全选远程"
- 点击"应用"后同步完成
- 点击"取消"后放弃同步

#### P1-2：冲突解决 — local-wins 模式

**步骤**：
1. 策略改为"local-wins"
2. 设备 A 和 B 都修改同一条笔记
3. 设备 B 同步

**预期**：
- 设备 B 的本地版本被推送到服务器
- 设备 A 再次同步时，看到设备 B 的版本

#### P1-3：冲突解决 — remote-wins 模式

**步骤**：
1. 策略改为"remote-wins"
2. 设备 A 和 B 都修改同一条笔记
3. 设备 B 同步

**预期**：
- 设备 A 的版本（在服务器上）覆盖设备 B 的本地版本

#### P1-4：标签同步

**步骤**：
1. 设备 A 创建新标签并关联到笔记
2. 设备 B 同步

**预期**：
- 标签出现在设备 B 上
- 笔记-标签关联正确

#### P1-5：附件同步

**步骤**：
1. 确认"同步附件"开关已开启
2. 设备 A 给笔记添加一个图片附件
3. 设备 B 同步

**预期**：
- 图片文件被下载到设备 B
- 在设备 B 上能正常显示图片

#### P1-6：版本历史同步

**步骤**：
1. 设备 A 创建一条笔记的版本历史
2. 设备 B 同步

**预期**：
- 版本历史出现在设备 B 上
- 可以查看和恢复历史版本

### P2 — 一般功能

#### P2-1：自动同步

**步骤**：
1. 开启自动同步，间隔设为 1 分钟（最短 5 分钟）
2. 在设备 A 上修改数据
3. 等待自动同步触发

**预期**：
- 到时间后自动触发同步
- 设备 B 的数据自动更新

#### P2-2：同步历史

**步骤**：
1. 执行几次同步操作
2. 查看同步历史

**预期**：
- 显示每次同步的时间和记录数
- 可以翻页查看更多历史

#### P2-3：连接测试

**步骤**：
1. 输入错误的服务器地址（如 `http://not-exist.com`）
2. 点击"测试连接"

**预期**：
- 显示"连接失败"的红色提示

#### P2-4：Token 过期处理

**步骤**：
1. 手动篡改数据库中的 access_token（改为无效值）
2. 触发同步

**预期**：
- 自动尝试刷新 token
- 如果刷新也失败，显示"登录已过期，请重新登录"
- 自动同步定时器被停止

#### P2-5：同步中状态显示

**步骤**：
1. 有较多数据时触发同步
2. 观察 UI 上的状态变化

**预期**：
- 状态依次显示：准备中 → 推送/拉取 → 同步附件 → 完成
- 进度条显示当前进度
- 顶栏云朵图标旋转

#### P2-6：并发同步防护

**步骤**：
1. 快速连续点击"立即同步"按钮两次

**预期**：
- 第二次点击被拒绝，提示"同步正在进行中"

---

### P3 — 边界情况

#### P3-1：无网络时同步

**步骤**：
1. 断开网络
2. 触发同步

**预期**：
- 显示连接错误
- 不影响本地功能使用

#### P3-2：空数据同步

**步骤**：
1. 新注册账号，本地没有任何数据
2. 触发同步

**预期**：
- 同步正常完成，推送 0 条，拉取 0 条

#### P3-3：大量数据同步

**步骤**：
1. 创建 100+ 条笔记
2. 触发同步

**预期**：
- 同步完成，数据完整
- 没有超时错误

#### P3-4：登出后同步

**步骤**：
1. 点击"登出"
2. 尝试触发同步

**预期**：
- 提示"未登录"或"同步未启用"

#### P3-5：应用重启后恢复冲突

**步骤**：
1. manual 模式下触发同步，出现冲突弹窗
2. 不要点"应用"或"取消"
3. 关闭应用再重新打开

**预期**：
- 重新打开后，冲突提示仍然存在
- 可以继续处理冲突

## 四、常见问题排查（FAQ）

### Q1：同步一直显示"准备中"然后超时

**可能原因**：
- 服务器没启动或地址错误
- 网络不通

**排查**：
1. 先点"测试连接"确认服务器可达
2. 检查服务器日志

### Q2：同步后数据没有变化

**可能原因**：
- 基线和当前状态完全一致（没有变化）
- 冲突策略设为 remote-wins，你的本地修改被覆盖了

**排查**：
1. 查看同步结果中的 pushed/pulled 数量
2. 确认冲突策略设置

### Q3：删除的笔记又回来了

**可能原因**：
- 另一台设备还没同步（它有旧版本会推回来）

**排查**：
1. 确保所有设备都同步过
2. 如果问题持续，检查 tombstone 是否正确写入

### Q4：附件同步失败

**可能原因**：
- 对象存储配置错误
- 附件文件太大

**排查**：
1. 检查服务器的存储配置
2. 查看服务器日志中的附件相关错误

### Q5：Token 过期后无法自动刷新

**可能原因**：
- refresh_token 也过期了
- 服务器端的 refresh 逻辑有问题

**排查**：
1. 重新登录
2. 检查服务器日志中的 refresh 请求

### Q6：manual 模式下弹窗没出现

**可能原因**：
- 当前同步没有产生冲突
- 前端事件监听未注册

**排查**：
1. 确认两台设备确实同时修改了同一条记录
2. 检查浏览器控制台（F12）中是否有 `sync-state-changed` 事件

## 五、测试检查清单

完成一次完整同步测试后，用这个清单验证：

```
[ ] 注册/登录正常
[ ] 首次同步能拉取所有数据
[ ] 增量同步只传输变化的数据
[ ] 双方各自修改不同记录 → 互相同步
[ ] 冲突自动解决（auto 模式）
[ ] 冲突手动解决（manual 模式弹窗）
[ ] 删除能传播到其他设备
[ ] 附件能上传和下载
[ ] 标签和关联关系正确同步
[ ] 版本历史正确同步
[ ] 自动同步定时器正常工作
[ ] 同步历史正确显示
[ ] 同步中 UI 状态正确（进度条、图标）
[ ] Token 过期能自动刷新或提示重新登录
[ ] 并发同步被正确阻止
[ ] 网络错误时不会崩溃
[ ] 应用重启后冲突状态能恢复
```
