# 诊断工具

诊断工具版块提供了应用运行时的调试和数据库管理功能。这些工具主要用于开发调试、性能排查和数据维护。

## SQL 日志

SQL 日志功能可以记录 QuantaNote 后端执行的所有 SQL 查询语句，帮助开发者了解数据库操作行为和排查问题。

### 启用/禁用

通过开关按钮控制 SQL 日志的启用状态。默认情况下 SQL 日志是关闭的，开启后会开始记录所有 SQL 操作。

| 选项 | 说明 |
|------|------|
| **开启** | 开始记录所有 SQL 查询语句 |
| **关闭**（默认） | 停止记录 SQL 查询 |

> **注意**：启用 SQL 日志会产生额外的 I/O 开销，建议仅在调试时开启，日常使用时保持关闭。

### 输出到控制台

启用后，SQL 日志会输出到应用的控制台（标准输出）。适合开发模式下实时查看 SQL 查询。

### 输出到文件

启用后，SQL 日志会写入到磁盘上的日志文件。默认开启，日志文件路径显示在设置页面中。

### 美化格式

启用后，SQL 查询语句会以格式化的方式输出，包括缩进和换行，便于阅读。关闭则以单行紧凑格式输出。

### 日志配置

#### 最大日志条目长度

控制每条 SQL 日志的最大字符数，超出部分会被截断。可选项：

| 选项 | 说明 |
|------|------|
| **1,000** | 适合只关注查询概要的场景 |
| **4,000**（默认） | 适合大多数调试场景 |
| **10,000** | 适合需要查看完整查询的复杂场景 |
| **50,000** | 适合需要完整日志的深度调试 |

## 日志文件位置

设置页面显示了 SQL 日志文件的完整路径。

复制路径后会显示复制结果提示。Windows 正式桌面应用会优先使用原生系统剪贴板；macOS/Linux 使用平台可用的剪贴板 API。

### 操作

| 操作 | 说明 |
|------|------|
| **复制路径** | 点击路径按钮，将日志文件路径复制到剪贴板 |
| **打开日志目录** | 点击「打开日志目录」按钮，在文件管理器中打开日志所在目录 |

### 默认路径

日志文件通常位于以下位置：

- **Windows**: `%USERPROFILE%\.quantanote\logs\`
- **macOS**: `~/.quantanote/logs/`
- **Linux**: `~/.quantanote/logs/`

## 清除 SQL 日志

点击「清除 SQL 日志」按钮可以清空日志文件的内容。此操作不可恢复，建议在清除前先备份有价值的日志。

**使用场景：**

- 日志文件过大，需要释放磁盘空间
- 开始新的调试会话，需要清空旧日志
- 日志中包含敏感信息，需要安全清除

## 数据库信息

数据库信息区域展示了 QuantaNote 本地数据库的当前状态。

### 数据库大小

显示数据库文件的当前大小。该信息每次打开设置页面时会自动刷新。

**影响因素：**

- 记录数量和内容长度
- 附件数据（如果存储在数据库中）
- 版本历史数量
- FTS5 全文搜索索引
- WAL（Write-Ahead Logging）日志文件

### 数据库路径

显示数据库文件的完整路径，点击路径按钮可以复制到剪贴板。

默认数据库路径：

- **Windows**: `%USERPROFILE%\.quantanote\quanta_note.sqlite`
- **macOS**: `~/.quantanote/quanta_note.sqlite`
- **Linux**: `~/.quantanote/quanta_note.sqlite`

## 优化数据库

### VACUUM 操作

点击「优化」按钮执行 SQLite 的 `VACUUM` 操作，该操作会：

1. **重建数据库文件**：消除碎片，优化存储空间
2. **清理 WAL 日志**：将 WAL 日志合并回主数据库文件
3. **减小文件大小**：回收已删除数据占用的空间
4. **优化查询性能**：重建索引，提升查询效率

**建议在以下情况执行优化：**

- 删除大量记录后
- 数据库文件明显变大但实际数据不多时
- 查询性能出现下降时
- 定期维护（例如每月一次）

> **注意**：VACUUM 操作可能需要一定时间，期间应用可能短暂无响应。建议在数据量较大时在空闲时段执行。
