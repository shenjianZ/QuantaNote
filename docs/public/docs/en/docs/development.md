# Development

Welcome to the QuantaNote development documentation. This section is designed for contributors who want to participate in QuantaNote development, covering everything from building from source to testing and contributing workflows.

Whether you want to fix a bug, add a new feature, or simply understand how QuantaNote works internally, you will find the information you need in the sections below. We recommend starting with "Building from Source" and "Project Structure" to quickly set up your development environment and understand the codebase organization.

## Sections

1. **[Building from Source](/docs/development/building)**

   Learn how to set up your local development environment, clone the repository, and build QuantaNote from source. Includes complete instructions for both development and production builds.

2. **[Technology Stack](/docs/development/tech-stack)**

   Explore the frontend and backend technologies used by QuantaNote, including React, TypeScript, Rust, Tauri, and other core dependencies with their versions.

3. **[Project Structure](/docs/development/project-structure)**

   Understand QuantaNote's directory layout and code organization, with detailed directory trees for both the frontend and backend.

4. **[Development Commands](/docs/development/commands)**

   Quick reference for common development commands, including frontend development, Tauri development, testing, formatting, and type checking.

5. **[Testing Guide](/docs/development/testing)**

   Learn about QuantaNote's three-tier testing strategy: frontend unit tests, Rust unit tests, and end-to-end tests.

6. **[Contributing](/docs/development/contributing)**

   Learn how to contribute to QuantaNote, including the fork workflow, branch naming conventions, code style requirements, and the PR submission process.

## Quick Start

If you are new to contributing, we recommend reading the sections in this order:

1. Building from Source — Set up your development environment
2. Project Structure — Understand the codebase organization
3. Development Commands — Familiarize yourself with common commands
4. Contributing — Learn the contribution workflow
