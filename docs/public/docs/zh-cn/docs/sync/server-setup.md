# 服务器设置

QuantaNote 的同步功能需要一个同步服务器。你可以使用自建的服务器来托管同步服务。本章将介绍如何配置和验证同步服务器连接。

## 同步服务器要求

QuantaNote 的同步服务器需要满足以下条件：

**基本要求：**

- 一个可运行同步服务的服务器（可以是本地服务器、VPS 或内网服务器）
- 服务器需要实现 QuantaNote 定义的同步 API 接口
- 建议使用 HTTPS 协议以确保数据传输安全

**API 接口：**

同步服务器需要提供以下核心 API 端点：

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/auth/register` | POST | 用户注册 |
| `/api/auth/login` | POST | 用户登录 |
| `/api/auth/refresh` | POST | 刷新 Token |
| `/api/auth/forgot-password` | POST | 忘记密码 |
| `/api/auth/reset-password` | POST | 重置密码 |
| `/api/sync/push` | POST | 推送本地变更 |
| `/api/sync/pull` | POST | 拉取远程变更 |
| `/api/sync/status` | GET | 获取同步状态 |

**自建服务器说明：**

如果你打算自建同步服务器，可以参考 QuantaNote 提供的服务端实现。服务端是一个独立的 Web 服务，可以部署在任何支持 Rust 运行时的环境中。

部署步骤概述：

1. 准备一台服务器（推荐 Linux 系统）
2. 编译并部署同步服务端程序
3. 配置数据库（服务端使用 PostgreSQL 或 SQLite）
4. 设置反向代理（如 Nginx）并启用 HTTPS
5. 确保防火墙开放相应端口

> **提示**：对于个人使用，一台低配 VPS 即可满足需求。同步数据量通常不大，主要取决于笔记数量和附件大小。

## 配置服务器地址

在 QuantaNote 客户端中配置同步服务器地址：

1. 打开 **设置 > 同步** 页面
2. 找到"服务器地址"输入框
3. 输入同步服务器的完整 URL，例如：
   ```
   https://sync.example.com
   ```
   或本地地址：
   ```
   http://localhost:3000
   ```
4. URL 末尾不要加斜杠 `/`

**支持的协议：**

- `https://` — 推荐，数据传输经过加密
- `http://` — 仅建议在本地开发或内网环境中使用

> **注意**：配置服务器地址后，你需要先测试连接，确认服务器可用后再进行注册或登录操作。

## 测试连接

配置服务器地址后，建议先进行连接测试：

1. 在设置 > 同步页面中，点击"测试连接"按钮
2. QuantaNote 会向服务器发送一个健康检查请求
3. 测试结果会显示在界面上：
   - **连接成功** — 显示服务器版本和响应时间
   - **连接失败** — 显示具体的错误原因

**常见连接问题：**

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 连接超时 | 服务器不可达或端口未开放 | 检查服务器状态和防火墙设置 |
| SSL 证书错误 | HTTPS 配置不正确 | 检查 SSL 证书是否有效 |
| 404 Not Found | URL 路径不正确 | 确认服务器地址和 API 路径 |
| 连接被拒绝 | 服务未启动 | 检查服务端程序是否正在运行 |

**测试成功后：**

连接测试通过后，你就可以进行下一步操作：

1. 注册新账号（首次使用）
2. 登录已有账号
3. 配置自动同步参数

详细的认证操作请参考 [认证](./authentication) 章节。
