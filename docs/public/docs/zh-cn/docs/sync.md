# 数据同步

QuantaNote 提供可选的数据同步功能，让你可以在多台设备之间保持笔记数据一致。同步功能基于自建的同步服务器，采用快照基线和三路差异比较算法，确保数据同步的准确性和完整性。

## 同步架构概述

QuantaNote 的同步引擎采用以下核心技术：

- **快照基线（Snapshot Baseline）** — 每次同步完成后记录一个基线快照，下次同步时以此为基础计算差异
- **三路差异比较（Three-way Diff）** — 对比本地变更、远程变更和基线版本，准确检测冲突
- **SHA256 内容哈希** — 使用 SHA256 算法对内容进行哈希，快速判断数据是否发生变化
- **墓碑机制（Tombstone）** — 通过墓碑标记已删除的记录，防止在其他设备上被重新同步回来

## 同步的数据类型

QuantaNote 会同步以下类型的数据：

| 数据类型 | 说明 |
|----------|------|
| Items | 笔记条目，包括标题、内容、创建/修改时间 |
| Tags | 标签定义，包括名称和颜色 |
| ItemTags | 笔记与标签的关联关系 |
| Attachments | 附件元数据（文件名、大小、类型）和附件文件内容 |
| Versions | 版本历史记录，包括每个版本的快照内容 |

## 冲突解决

当多台设备同时编辑同一条记录时，同步引擎会检测到冲突。QuantaNote 提供四种冲突解决策略：

- **Auto（自动）** — 基于时间戳自动选择最新版本
- **Local-wins（本地优先）** — 冲突时始终保留本地版本
- **Remote-wins（远程优先）** — 冲突时始终采用远程版本
- **Manual（手动）** — 逐条冲突手动选择保留哪个版本

详细的冲突解决说明请参考 [冲突解决](./conflict-resolution) 章节。

## 安全性

同步过程中的安全性保障：

- **认证机制** — 使用邮箱/密码注册和登录
- **Token 管理** — Access Token + Refresh Token 双令牌机制
- **设备标识** — 每个设备拥有唯一的设备 ID，用于追踪变更来源
- **传输安全** — 建议配合 HTTPS 使用同步服务器
