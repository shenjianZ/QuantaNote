# 同步数据

完成认证后，你就可以开始在设备之间同步数据了。QuantaNote 提供手动和自动两种同步方式，并实时显示同步状态和进度。

## 手动同步

手动同步适用于以下场景：

- 首次配置同步后的初始同步
- 在其他设备上做了重要修改后
- 自动同步被禁用时
- 网络恢复后立即同步

**操作步骤：**

1. 确保已登录同步账号
2. 在 **设置 > 同步** 页面中，点击"立即同步"按钮
3. 或者在顶部状态栏中点击同步图标触发同步

**同步流程：**

QuantaNote 的同步过程分为以下阶段：

1. **计算本地差异** — 自上次同步基线以来，检测本地新增、修改和删除的记录
2. **推送到服务器** — 将本地变更上传到同步服务器
3. **从服务器拉取** — 获取服务器端的最新变更
4. **冲突检测** — 对比本地和远程变更，检测是否存在冲突
5. **冲突解决** — 根据配置的策略解决冲突（如果有）
6. **应用变更** — 将远程变更合并到本地数据库
7. **更新基线** — 记录新的同步快照作为下次同步的基线

**进度显示：**

同步过程中，状态栏会实时显示当前进度：
- 同步阶段名称（如"推送中"、"拉取中"）
- 已处理记录数 / 总记录数
- 同步附件时显示"上传附件"或"下载附件"，以及已处理附件数 / 附件总数
- 预计剩余时间（可选）

附件进度目前按“附件个数”统计，不是按字节统计。单个大附件传输期间，计数可能要等请求完成后才前进；同步中断后也会重新传输未完成的附件，当前版本尚未支持断点续传。

## 自动同步

自动同步功能可以按照设定的时间间隔自动执行同步操作。

**配置自动同步：**

1. 在 **设置 > 同步** 页面中，找到"自动同步"选项
2. 开启自动同步开关
3. 设置同步间隔（单位：分钟）

**推荐配置：**

| 使用场景 | 建议间隔 | 说明 |
|----------|----------|------|
| 单人使用 | 10-30 分钟 | 适中频率，兼顾及时性和性能 |
| 多人协作 | 1-5 分钟 | 高频同步，减少冲突概率 |
| 低频使用 | 60 分钟 | 减少不必要的网络请求 |

**自动同步行为：**

- 仅在应用运行时生效
- 如果上一次同步尚未完成，不会重复触发
- 网络不可用或同步失败时会进入离线队列，并在下一次退避时间到达后自动重试
- 同步设置页和状态栏会显示失败次数、下次重试时间和最近一次错误

## 离线队列与重试

同步失败不会丢弃本地数据。QuantaNote 会在本地持久化一条待同步队列状态：

- 队列只保存待同步状态、失败次数、下次重试时间和错误信息，笔记数据仍保存在本地 SQLite 中
- 临时错误采用递增退避重试，应用关闭后重新打开仍会恢复重试计划
- 在设置页点击“暂停同步”后，不会继续自动重试；点击“继续并重试”会清除当前等待时间并恢复同步
- 同步成功后，队列和失败计数会清零

## 同步状态

QuantaNote 在状态栏中提供实时的同步状态指示器：

| 状态 | 图标 | 说明 |
|------|------|------|
| 空闲 | 绿色对勾 | 已登录，无待同步内容 |
| 同步中 | 旋转图标 | 正在执行同步操作 |
| 待同步 | 蓝色圆点 | 有本地变更等待同步 |
| 错误 | 红色感叹号 | 同步失败，需要关注 |
| 已暂停 | 暂停图标 | 自动同步和失败重试已暂停 |
| 未登录 | 灰色图标 | 未配置同步或已登出 |

**错误处理：**

当同步出现错误时：

- 状态栏会显示红色错误图标
- 点击图标可以查看详细错误信息
- 常见错误包括网络超时、服务器不可达、认证失败等
- 大多数临时错误会按照离线队列的重试计划自动重试

当前同步设置页还会展示本机的最后同步时间、同步队列和重试状态。登录同步账号后，设置页还会列出该账号的有效设备会话及最近活动时间。除当前设备外，可以点击“撤销会话”使对应设备的 Refresh Token 失效；被撤销的设备需要重新登录。设备列表只显示设备 ID，不上传设备名称或额外的硬件信息。

## 同步内容

同步引擎会处理以下五类数据：

### Items（笔记条目）

- 笔记标题和正文内容
- 创建时间和修改时间
- 是否置顶等标记信息

### Tags（标签）

- 标签名称和颜色
- 标签的唯一标识（UUID）

### ItemTags（关联关系）

- 笔记与标签之间的多对多关联

### Attachments（附件）

- 附件元数据（文件名、大小、MIME 类型）
- 附件文件内容（按附件请求上传和下载，并通过内容哈希去重）

### 附件传输现状

当前内置云同步的附件接口工作方式如下：

1. 客户端先提交本地附件内容哈希，服务端返回缺失附件和远端附件元数据
2. 上传使用单个完整请求体，下载使用单个完整响应体
3. 服务端当前没有 `Range`、`Content-Range`、上传会话或分片偏移量协议
4. 因此进度显示是附件级进度，不代表单个文件的字节级进度；请求失败后不能从中断位置继续

真正实现断点续传需要客户端、HTTP 接口和存储后端同时支持上传会话、分片校验、幂等提交、失败分片清理，以及下载范围响应；在协议升级前，客户端不会假装支持断点续传。

### Versions（版本历史）

- 每次保存时的版本快照
- 版本的创建时间和内容摘要

> **提示**：附件和版本历史的数据量通常最大。如果同步速度较慢，可以检查附件文件大小。

## 同步历史

QuantaNote 记录每次同步操作的详细信息。

**查看同步历史：**

1. 在 **设置 > 同步** 页面中，找到"同步历史"区域
2. 以时间倒序显示最近的同步记录

**历史记录信息：**

| 字段 | 说明 |
|------|------|
| 同步时间 | 本次同步完成的时间 |
| 快照 ID | 同步完成后生成的基线快照标识 |
| 推送数量 | 本次同步上传的变更数 |
| 拉取数量 | 本次同步下载的变更数 |
| 冲突数量 | 检测到并解决的冲突数 |
| 同步状态 | 成功 / 部分成功 / 失败 |

同步历史可以帮助你：

- 追踪数据变更的时间线
- 了解各设备之间的同步频率
- 诊断同步问题

## Token 过期

QuantaNote 使用双令牌机制进行认证：

- **Access Token** — 短期有效，用于 API 请求
- **Refresh Token** — 长期有效，用于刷新 Access Token

**Token 过期行为：**

1. 当 Access Token 过期时，系统自动使用 Refresh Token 获取新的 Access Token
2. 如果 Refresh Token 也过期，系统会自动执行登出操作
3. 登出后需要重新输入邮箱和密码进行登录
4. 登出不会影响本地数据

> **提示**：如果你长时间未使用 QuantaNote（超过 Refresh Token 的有效期），下次打开时可能需要重新登录。
